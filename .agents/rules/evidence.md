# Evidence and Verification Rules

This document outlines the strict guidelines for gathering and validating verification evidence.

## Core Rules

1. **Evidence Over Claims**: Reports generated by Workers, Reviewers, and Judges are claims, not proof. Final Approach Control must verify raw exit codes and command outputs from actual runs.
2. **No False Pass**: Do not report `PASS` unless the command was actually executed and succeeded. If a test/lint was skipped due to missing config, mark it as `SKIPPED_NO_COMMAND`.
3. **P1/P2 Blocker Invariant**: Under no circumstances can a task be approved if there is an open finding of severity `P1` or `P2`.
4. **Approval Terminology**: Single word `APPROVED` is forbidden. Commits can only be approved with `APPROVED FOR COMMIT ONLY`. Push/Release requires separate user validation.

## Command Status Matrix

- `PASS`: Success run.
- `FAIL`: Non-zero exit code or error output.
- `SKIPPED_NO_COMMAND`: No command resolved/configured.
- `SKIPPED_NOT_APPLICABLE`: Verification not applicable.
- `BLOCKED_ENVIRONMENT`: Execution blocked by lack of tools/dependencies.
- `NOT_RUN`: Verified command was not executed.
