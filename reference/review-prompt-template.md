# 교차 AI 리뷰 지시문 템플릿

> 고성능 AI에게 코드 검증을 요청할 때 사용하는 범용 템플릿.  
> 검증 범위를 제한하지 않고, 맥락만 충분히 제공한다.

---

## 사용법

1. `<placeholder>` 부분을 실제 내용으로 교체
2. 코드는 전체를 포함 (발췌 금지)
3. 마지막 줄은 반드시 열린 질문으로

---

## 템플릿

```markdown
# <프로젝트명> — 코드 검증 요청

## 배경

<프로젝트가 뭔지, 어떤 기술 스택인지 2~3줄>

## 이전 리뷰 이력

<없으면 "첫 번째 리뷰입니다."로 대체>

| 지적 | 수정 |
|---|---|
| <1차 지적사항> | <수정 내용> |
| ... | ... |

## 의도적 미구현 (MVP 범위 밖)

- <의도적으로 구현하지 않은 항목 1>
- <항목 2>
- ...

## 아키텍처

\```
<ASCII 다이어그램 또는 텍스트 설명>
외부 클라이언트 → 서버 → 브릿지 → 외부 도구
\```

## 현재 코드

### 1. `<파일 경로>`

\```<언어>
<전체 소스 코드>
\```

### 2. `<파일 경로>`

\```<언어>
<전체 소스 코드>
\```

<필요한 만큼 반복>

## 빌드/테스트 상태

\```
<빌드 커맨드와 결과>
오류 0개, 경고 N개
테스트: X/Y 통과
\```

## 검증 요청

위 코드의 정확성, 안정성, 보안, 호환성을 자유롭게 검증해주세요.
```

---

## 안티패턴

### ❌ 범위를 제한하는 지시문

```markdown
다음 3개만 확인해주세요:
1. BOM 적용 여부
2. --print 옵션 적용 여부
3. Request ID 사용 여부
```

→ 새로 생긴 문제를 못 잡음

### ❌ 코드를 발췌하는 지시문

```markdown
핵심 부분만 보여드리겠습니다:
// ... (생략) ...
```

→ 생략된 부분에 버그가 있을 수 있음

### ❌ 판단을 유도하는 지시문

```markdown
이 코드는 잘 작성되었다고 생각합니다. 확인해주세요.
```

→ 확증 편향 유발
