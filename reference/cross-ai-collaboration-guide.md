## 세션 요약

### 프로젝트

Claude4Net의 `/agy-server` — OpenAI 호환 API 프록시 서버  
C# HttpListener ↔ PowerShell TCP 브릿지 ↔ agy CLI 에이전트

### 반복 히스토리

| 라운드 | 구현 | 리뷰 | 결과 |
|---|---|---|---|
| 1 | 서브 에이전트 | 테르키르도 | 기본 기능 동작 |
| 2 | 서브 에이전트 (리팩토링) | GPT 5.6 | **REJECTED** — P1 3건, P2 6건 |
| 3 | 서브 에이전트 (P1/P2 수정) | GPT 5.6 | **REJECTED** — 수정 중 인코딩 손상 발생 |
| 4 | 테르키르도 직접 | 빌드+파서 검증 | P1/P2 해결, 일부 P2 잔존 |
| 5 | GPT 5.6 (리뷰+구현) | 테르키르도 | **APPROVED** — 437줄 재설계 + 테스트 7개 |

### 핵심 발견

- 단일 AI의 4번 반복 < 고성능 AI의 1번 재설계
- 리뷰 AI와 구현 AI를 분리하면 편향이 줄어듦
- 서브 에이전트에게 인코딩/보안/동시성 작업을 맡기면 위험

## 교차 AI 워크플로우

### 역할 정의

```
┌─────────────────────────────────────────────┐
│  주인님 (Human)                              │
│  - 최종 의사결정                              │
│  - AI 간 결과물 전달                          │
│  - 승인/거부                                 │
└──────────┬──────────────────────────────────┘
           │
     ┌─────┴─────┐
     ▼           ▼
┌─────────┐ ┌──────────┐
│ 구현 AI  │ │ 리뷰 AI   │
│ (any)    │ │ (GPT 5.6) │
│          │ │           │
│ 코드 생성 │ │ 재현 검증  │
│ 리팩토링  │ │ 보안 감사  │
│ 테스트   │ │ 아키텍처   │
└─────────┘ └──────────┘
     ▲           │
     │     Findings
     │           ▼
┌──────────────────┐
│ 테르키르도         │
│ (Orchestrator)    │
│                   │
│ - 지시문 작성      │
│ - 결과 분석        │
│ - 수정 판단        │
│ - 직접 수정 or     │
│   서브 에이전트     │
└──────────────────┘
```

### 워크플로우 순서

```
1. 주인님 요청 수신
2. 테르키르도: scope/risk 분류 → Tier 결정
3. 구현 AI에게 코드 생성 지시
4. 테르키르도: 1차 코드 검토 (빌드, 기본 구조)
5. 리뷰 지시문 작성 → 주인님이 고성능 AI에 전달
6. 고성능 AI 리뷰 결과 수신
7. 테르키르도 + 주인님: 리뷰 분석
8. 수정 필요 시:
   - 같은 영역 2회 실패 → 테르키르도 직접 수정
   - 인코딩/보안/동시성 → 테르키르도 직접 수정
   - 단순 로직 수정 → 서브 에이전트
9. 재검증 (5번으로 돌아감)
10. APPROVED → 커밋
```

## 규칙 (Rules)

### Rule 1: 서브 에이전트 파일 무결성 검증

```
서브 에이전트가 스크립트 파일(.ps1, .sh, .bat)을 수정한 경우:
1. view_file로 전체 내용을 확인한다 (grep만 하지 않는다)
2. 인코딩 변환이 포함된 경우, 변환 전후 줄 수를 비교한다
3. 한글/유니코드 주석이 포함된 파일은 인코딩 손상 여부를 특별히 주의한다
```

**사건:** code-worker가 UTF-8 BOM 변환 시 한글 주석과 코드를 같은 줄로 합침  
**교훈:** grep은 패턴만 확인, 줄 무결성은 확인 불가

### Rule 2: 크로스플랫폼 스크립트 영문 주석

```
.ps1, .sh, .bat 등 크로스플랫폼 스크립트:
- 주석과 문자열 리터럴에 영문만 사용
- 한글 설명이 필요하면 docs/에 별도 작성
- 이모지 금지 (호환성)
```

**사건:** 한글 주석이 인코딩 변환 과정에서 깨짐 → 코드와 합쳐짐  
**대안:** GPT 5.6은 영문 주석만으로 108줄 깨끗한 스크립트 작성

- 주석 최소, 구조로 의도를 표현
- 에이전트 도구를 적극 활용

## 실패 사례와 교훈

### 사례 1: 인코딩 변환으로 스크립트 파괴

```
[원인]
서브 에이전트가 agy-bridge.ps1을 UTF-8 BOM으로 변환
→ 한글 주석의 줄바꿈이 삭제
→ 주석과 코드가 같은 줄로 합쳐짐
→ 런타임 파싱 불가

[재현]
Line 11: # ANSI 코드 제거용 패턴$ansiPattern = "`e\[[0-9;]*m"
         ^^^^^^^^^^^^^^^^^^^ ← 주석으로 처리됨 (변수 할당 사라짐)

Line 36: # 서버로부터 프롬프트 대기    while ($true) {
         ^^^^^^^^^^^^^^^^^^^^^^^^^^ ← while 블록이 주석 안으로 들어감

[교훈]
1. 인코딩 변환은 줄 수 비교로 검증
2. 스크립트에 한글 주석을 쓰지 않으면 원천 방지
```

### 사례 2: 인프라 실패를 HTTP 200으로 반환

```
[원인]
SendPromptToBridgeAsync가 브릿지 미연결/타임아웃 시
문자열 "[Agy Proxy] Bridge not connected..." 반환
→ HandleChatCompletionAsync가 이를 정상 assistant 응답으로 래핑
→ 클라이언트는 HTTP 200 + "assistant: Bridge not connected..." 수신

[해결]
전용 예외 클래스 도입:
- BridgeNotConnectedException → 503
- BridgeSendException → 503
- BridgeTimeoutException → 504
- BridgeDisconnectedException → 503
- BridgeProcessException → 502

[교훈]
인프라 실패를 절대 문자열로 반환하지 않는다.
예외를 throw하고 HTTP 핸들러에서 적절한 status code로 매핑한다.
```

### 사례 3: FIFO 큐로 동시 요청 처리

```
[원인]
Queue<TaskCompletionSource<string>>로 응답을 FIFO 매칭
→ 동시 요청 시 응답이 다른 요청에 배달
→ 타임아웃된 요청의 TCS가 큐에 남아 다음 응답을 훔침

[해결]
ConcurrentDictionary<string, TCS> + Full GUID Request ID
+ SemaphoreSlim으로 StreamWriter 직렬화
+ 통합 finally 블록으로 모든 경로에서 정리

[교훈]
비동기 응답 매칭에 FIFO 큐를 쓰지 않는다.
ID 기반 상관관계 매핑을 사용한다.
```

## 리뷰 지시문 작성법

### 좋은 예 (범용적)

```markdown
# [프로젝트명] — 코드 검증 요청

## 배경
[프로젝트 설명 2~3줄]

## 이전 리뷰 이력 (있으면)
[지적사항 + 수정 내역 테이블]

## 의도적 미구현 (MVP 범위 밖)
[리스트]

## 아키텍처
[다이어그램]

## 현재 코드 (전체)
[모든 관련 파일 전문]

## 빌드 상태
[빌드/테스트 결과]

## 검증 요청
위 코드의 정확성, 안정성, 보안, 호환성을 자유롭게 검증해주세요.
```

### 나쁜 예 (범위 제한)

```markdown
## 검증 요청
다음 3개 항목만 확인해주세요:
1. BOM이 적용되었는지
2. --print 옵션이 적용되었는지
3. Request ID가 사용되는지

← 이렇게 하면 새로 생긴 문제를 못 잡음
```

### 핵심 원칙

1. **범위 제한 금지** — AI가 알아서 찾게 한다
2. **맥락은 최대한** — 코드, 아키텍처, 이력 전부 제공
3. **의도적 미구현 명시** — 같은 지적의 반복 방지 (그러나 AI 판단을 제한하지 않음)
4. **마지막 줄** — "자유롭게 검증해주세요"
