## 1. Official Verification Standard

The only official release gate is:

```powershell
.\scripts\verify-release.ps1
```

That gate must validate:

1. Standard Build
2. Strict Nullable Build
3. Unit and Integration Tests
4. CLI Smoke Test using `--smoke-exit`

Do not treat these as official standards:

- `dotnet run` pipe validation
- `/exit` pipe validation
- DLL stdin pipe validation

## 3. Operating Roles

### Gemini CLI Worker

- Implements assigned work
- Modifies code and tests
- Runs the official release gate
- Does not commit or push

### Gemini 3.1 Pro First Reviewer

- Reviews worker output
- Checks staged and unstaged diffs
- Re-runs the release gate when needed
- Writes P1/P2/P3 findings
- If work is not ready, writes the correction prompt
- Does not escalate to Codex until blocking findings are cleared
- Does not commit or push

### Codex Final Controller

- Verifies after the first reviewer says work is complete
- Samples the actual repository state instead of trusting reports
- Makes the final commit/push decision
- May directly perform K012 maintenance cleanups when they are small, scoped, and evidence-backed

2. new required files are not left untracked
3. staged content matches the actual scope
4. `.\scripts\verify-release.ps1` passes
5. `IMPLEMENTATION_PROGRESS.md` reflects the real result
6. this file points to the correct operating state
7. there is no unresolved P1 blocking issue
8. remaining risks are documented honestly

If these conditions are not met, use one of:

- `Partial`
- `In Progress`
- `Implemented, Not Operationalized`

Do not use `Completed`.
