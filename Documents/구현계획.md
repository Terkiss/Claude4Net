## 0. Product Direction

Claude4Net-App is moving from a Windows-stable agent CLI into an enterprise-grade .NET agent framework.

The product identity is:

> Claude4Net-App is a trusted execution environment where .NET developers can safely and transparently delegate real development work to AI agents.

The next roadmap is based on three product pillars from the 2026-05-06 insight report:

1. Intelligence: reusable and self-improving skill assets
2. Orchestration: observable, resumable, file-backed agent work
3. Safety: explicit permission, approval, diff, and doctor gates

GUI is out of scope for at least one year. The roadmap focuses on `Claude4Net.Cli`, `Spectre.Console` TUI, Discord integration, and machine-readable status.

## 3. Operating Roles

### Gemini CLI Worker

- Implements assigned work
- Modifies code, tests, and docs
- Runs the official release gate
- Does not commit or push

### Gemini 3.1 Pro First Reviewer

- Reviews worker output
- Checks staged and unstaged diffs
- Re-runs the release gate when needed
- Writes P1/P2/P3 findings
- If work is not ready, writes the correction prompt
- Does not escalate to Codex until blocking findings are cleared
- Does not commit or push

### Codex Final Controller

- Reads the actual repository state before trusting reports
- Makes final approval, commit, and push decisions
- May directly perform small, scoped, evidence-backed documentation or hygiene corrections
- Keeps branch policy and release gates aligned

## 4. Phase 2 Roadmap From Insight 0506

### P0 Reliability: Safety and Preflight Diagnosis

Goal:

Make the environment, workspace, permissions, providers, and tool risk visible before an agent starts real work.

Target outputs:

- `claude4net doctor`
- `claude4net doctor --output-format json`
- `PermissionMode` enum
- `PermissionEnforcer`
- `CommandRiskClassifier`
- CLI `--permission-mode` flag
- workspace-outside write block tests
- symlink escape tests
- binary write safety checks

Priority reason:

Developers cannot trust AI file and terminal automation until safety gates are predictable and inspectable.

### P1 Visibility: Observable and Resumable Sessions

Goal:

Make long-running agent work observable, resumable, and easy to audit.

Target outputs:

- `.claude4net/sessions/` standard layout
- `AgentSessionStore`
- `AgentTaskBoard`
- `AgentProgressWriter`
- `WorkflowGateEvaluator`
- `task-board.json`
- `progress-{agent}.jsonl`
- `result-{agent}.md`
- `claude4net status`
- `claude4net resume {sessionId}`
- Spectre.Console TUI task board

Priority reason:

Claude4Net-App must become an operations console for agent work, not only a chat loop.

### P2 Developer Workflow: Diff Approval and Execution Control

Goal:

Let users inspect and approve AI-proposed changes and risky terminal actions before they happen.

Target outputs:

- Diff viewer
- file-level approve/reject
- hunk-level approve/reject if feasible
- `IUserApprovalHandler` request model refinement
- dangerous command approval flow
- terminal execution status panel
- JSON status output standard

Priority reason:

Developers need to know what AI changed before trusting it with real repositories.

### P3 Intelligence: Skill Evolution and Reuse

Goal:

Make Claude4Net-App smarter over time by turning successful work patterns into tracked, versioned skill assets.

Target outputs:

- `SkillRegistryService`
- `.skill_id` sidecar support
- `SkillQualityTracker`
- `SkillEvolutionPlanner`
- `SkillLineageStore`
- `SkillIdResolver`
- skill quality metrics
- hallucinated skill recovery
- diff-based skill evolution proposal
- `!reflect` or background reflection job

Priority reason:

Reusable skills reduce repeated token cost and preserve project-specific agent knowledge.
